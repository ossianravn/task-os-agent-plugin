# 011 — `verify` ships in stage 1

Task OS grew out of an incident in which a figure reached a client before anyone checked it against a source that could settle it. Only `verify` catches that, and SPEC.md had it arrive in stage 2, after the week of real use in which the same thing could happen again. Stage 1 therefore ships `verify` as a fifth skill, written by hand like the other four. It reads the draft, `work/ways-of-working.md`, each communication document and each recipient's person record; finds the records behind each statement in `work/records/`, skipping superseded ones; opens their sources; and checks scope, freshness and whether the source can settle the statement (`source_settles` on the record, `cannot_show` on the system record). It classes each statement as supported, qualified, conflicting or evidence-needed, runs the communication documents' own checklists, and returns a table and line-level edits. The draft keeps its structure, order and wording; additions are offered separately, and edits are applied only on the user's word. The cost is one more skill description in every session (192 characters). The managed block (`v0.5`) sends everything addressed to someone else through it. Stage 2 keeps the steps and moves the searching onto `claims` and `recall`.
