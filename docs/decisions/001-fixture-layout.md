# 001 — Fixture layout and expected results

Each fixture lives in `fixtures/<name>/` in three parts. `folder/` is the engagement folder exactly as the user has it before Task OS. `inputs/` holds material a session brings in later, such as a draft to verify. `expected/expected.yaml` holds the results a correct run must produce. `expected/` sits beside `folder/`, not inside it, so `adopt scan` never sees it. E2e tests copy `folder/` to a temporary directory, run against the copy, and compare the copy with the committed original for the byte-for-byte check. Expected records are matched by type, basis, state and the sources they cite, never by id, because ids are minted at run time. Each fixture states an `as_of` date and tests pin the clock to it, so the next action and freshness checks do not depend on the day the tests run.
