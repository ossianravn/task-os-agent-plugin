# 008 — Stage 1 setup skips connection checks and ends with brief

Two steps of `setup` in SPEC.md section 9 depend on parts that arrive later, so the stage 1 skill leaves them out. Step 4 checks each connection and writes `.taskos/local/host.yaml`; stage 1 records only each system's `access` in its system record, because the connection states pay off only when `doctor` reports them (stage 3) and `host.yaml` also holds the dist path that the stage 2 launcher needs. Step 6 ends by opening a fresh session in the other host and showing `recall` finding the task's result; stage 1 asks the user to run `brief` there instead, which shows the handoff and its next action, because `recall` arrives with the core in stage 2. Stage 2's `setup` adds both steps back as the spec describes them.
